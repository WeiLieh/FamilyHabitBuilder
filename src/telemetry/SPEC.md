# Telemetry: module spec

[2026-10-31 10:09 SGT] The **current rules** of the Telemetry module: recording events from every module and calculating the owner's 10 success metrics. Rule IDs are permanent. The dated history of each decision is in the change notes of the master spec, [docs/SPEC.md](../../docs/SPEC.md).

## Purpose
[2026-10-31 10:09 SGT] Show whether the app works for families: are parents active, are habits forming, is the app "never pushy". Telemetry **listens to events from every module** (dotted lines in [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)); events are recorded from the Datastore step onwards, so no data is lost before the metric calculations are built (development order, step 6).

## Rules
- **5.2** [2026-11-09 00:08 SGT] **Prompted or unprompted** (metric 7). A log is **prompted** if that **same behaviour** was nudged **earlier the same Singapore day**, whatever the parent replied (✅ Done, 😴 Not today, the keyboard, or nothing). Every other log is **unprompted**: a nudge for a different behaviour does not make it prompted, and a nudge from an earlier day does not count. Used by metric 7 and Variable rewards (rule 7.2). Mirrors metric 8 (rule 10.1), so each log counts for exactly one of the two. *(decided 28 Oct, changed 9 Nov)* Not yet tested (nothing built).
- SUPERSEDED [2026-11-09 00:08 SGT] **5.2** **Unprompted** = no nudge message in the 4 hours before (metric 7). Used by Variable rewards (rule 7.2). *(decided 28 Oct)* Not yet tested (nothing built).
- [2026-11-09 00:10 SGT] **Metric 8 window changed** (owner, 9 Nov): a nudge counts as "followed by a logged action" when **the same behaviour is logged later the same Singapore day** (was "within 24 hours"). Together with rule 5.2, every log counts toward metric 8 or metric 7, never both. Done in the spreadsheet: version 2 has the new metric 7 and 8 definitions and settings.
